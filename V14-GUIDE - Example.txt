=====================================================================
  GAME SAVE MANAGER v14 - WHAT EACH PART IS AND HOW TO USE IT
=====================================================================
How to open a terminal (Konsole) IN the program's folder (Steam Deck)
  1. Desktop mode. Open Dolphin, go to the folder with savemanager.py
     (for example Desktop > files).
  2. Right-click an EMPTY gap in the file area (not on a file).
  3. Choose "Open Terminal Here". A black window opens inside that folder.
  Everything below that says "type" means: type it there, then press Enter.
  (Windows: open the folder, click the address bar, type  cmd  and press Enter.
   Use  python  instead of  python3  on Windows.)

---------------------------------------------------------------------
1. HEALTH CHECK  (menu K, or:  python3 savemanager.py health)
---------------------------------------------------------------------
A one-screen list of [ OK ] / [WARN] / [FAIL]: is Games.json valid, are
there duplicates or typos, does any entry still need one of your IDs,
is Tailscale running, can this device reach the NAS and write to it, how
fast is it, how much space is free, is the clock close to the NAS clock,
are uploads waiting or stuck. Run it when something feels wrong.
(Time zones do not matter for saves - only a clock that is wrong.)

---------------------------------------------------------------------
2. NAS MOUNTS BY ITSELF AFTER A RESTART  (Steam Deck)
---------------------------------------------------------------------
Set it up once:
  1. Run NasMount.sh once first and answer  y  to "Save this login".
  2. Open a terminal in the folder (see top) and type:
         bash NasAutoMount.sh
     Type your Deck password when asked (nothing shows while typing).
     It makes a safety copy of /etc/fstab first.
Test it:
  3. Restart the Deck (Steam button > Power > Restart).
  4. Open the manager, or in a terminal type:  ls ~/nas
     The first time something opens the folder, Linux connects it.
  5. Check:  bash NasAutoMount.sh --status
     or run the Health check (K). It says whether it is working.
Undo:  bash NasAutoMount.sh --remove
If the NAS is unreachable the first try fails after about 15 seconds and
the program just saves to the local backup folder. In Settings (menu G)
set "Seconds to wait for the NAS to answer" to 8.
A SteamOS update can remove this; the Health check shows it, run it again.

---------------------------------------------------------------------
3. GAME LOOKUP  (menu N > 4)
---------------------------------------------------------------------
Type a game name. It searches Steam, shows genres and the most-voted
tags, reads the save folder PCGamingWiki lists, and turns it into a path
for THIS device: a Windows folder on the PC, or the game's Proton folder on
the Deck. Folders that already exist here are marked. You choose, it
saves the entry to Games.json (the old file is kept as Games.json.bak-...).
It needs internet while you do this and may need adjusting the first time.

---------------------------------------------------------------------
4. STEAM SETUP  (menu O, or:  python3 savemanager.py steamsetup)
---------------------------------------------------------------------
Puts the right launch option into your non-Steam shortcuts in one go
(shortcuts that match a game in Games.json by name; Switch games are also
matched by the title ID in the rom's file name). Old options are kept.
Steam Deck, DESKTOP mode only:
  - It shows the list and asks ONCE "Go ahead? [y/N]" (type y).
  - Then it closes Steam, edits the file (a .bak copy is made) and starts
    Steam again by itself. You do not need a keyboard after the question.
  - No keyboard at all? Run it with the answer built in:
        python3 savemanager.py steamsetup --yes
Gaming mode: it refuses (Steam is the screen there).

---------------------------------------------------------------------
5. SETTINGS FROM THE MENU  (menu G)
---------------------------------------------------------------------
Pick a number, type the new value. Examples: how often timed backups run,
how many versions to keep, what to do when both devices changed a save
(Ask / AutoNewest / AlwaysLocal), this device's name and backup folders.
Games.json is saved with a backup copy each time.

---------------------------------------------------------------------
6. ONE ENTRY FOR EVERY GAME IN AN EMULATOR
---------------------------------------------------------------------
Switch: the single "Switch" entry already finds every game that has a save.
Other emulators (RPCS3, PPSSPP, Azahar/Citra, ShadPS4, Dolphin Wii):
add ONE entry like this (Deck path has its own key):
  {
    "Name": "RPCS3",
    "PerGameSource": "D:\\Games\\z Emulators\\PS3 - RPCS3\\dev_hdd0\\home\\00000001\\savedata",
    "PerGameSourceSteamDeck": "/home/deck/.config/rpcs3/dev_hdd0/home/00000001/savedata",
    "PerGameLabel": "RPCS3",
    "Process": "rpcs3",
    "Platform": "Emulators"
  }
Every sub folder with a save becomes its own game ("RPCS3 - <name>") that is
backed up, restored and kept in step between devices separately. A folder
with no name yet shows its folder name: run  python3 savemanager.py library
to name them (saved in EmulatorTitles.json).

---------------------------------------------------------------------
7. THE "SAVING..." WINDOW  (Deck)
---------------------------------------------------------------------
After a game closes, if the program "zenity" is installed, a small window
shows what is being worked on (Saving..., Uploading... Done). It pulses; it
has no percentage bar because uploads are time-limited. In Settings (G) you
can switch it off. If you never see it, zenity is probably not installed.

---------------------------------------------------------------------
8. MANY MORE VERSIONS
---------------------------------------------------------------------
Default now: the newest 100 versions per game are kept, and versions older
than 30 days are thinned to one per day. Change in menu G:
  "Versions to keep per game"  -  YOUR Games.json says 15, change it!
  "Thin versions older than N days"
A single game can have its own  "VersionCount": 300  in Games.json.

---------------------------------------------------------------------
9. DASHBOARD AND VERIFY  (menu D, and:  python3 savemanager.py verify)
---------------------------------------------------------------------
Dashboard: games with a save here that have NEVER been backed up or not
for 14 days, uploads still waiting for the NAS, the most recent backups,
space used. Verify: re-reads every backup and checks it still matches the
fingerprint taken when it was saved (finds damaged or cut-off copies).

---------------------------------------------------------------------
10. UPGRADING TO A NEW VERSION  (menu U, or:  python3 savemanager.py upgrade)
---------------------------------------------------------------------
I will send you a zip like  GameSaveManager-v14.1.zip.
  1. Download it into the SAME folder as savemanager.py (for example
     Desktop > files). (Anywhere in Downloads works too.)
  2. Open a terminal in that folder (see the top of this guide).
  3. Type:      python3 savemanager.py upgrade GameSaveManager-v14.1.zip
     (just a file name is fine when the zip is in the folder). Or type only
         python3 savemanager.py upgrade
     and it lists the zips it finds - pick one by number.
  4. It shows "Installed version / New version" and asks  y/N.
What it does:
  - Copies your CURRENT program files into
        Backups / Program versions / v14.0_<date and time> /
    (inside the same folder, named with the version you are leaving).
  - Installs the new program files.
  - Adds NEW games/categories/titles to Categories.json, SwitchTitles.json,
    EmulatorTitles.json but keeps everything you edited.
  - Does NOT touch Games.json, MyIDs.json, State, Logs or your backups.
Undo:  python3 savemanager.py upgrade --rollback   (puts the newest saved
copy back). Then restart the program.

---------------------------------------------------------------------
IF A GAME WILL NOT START FROM STEAM
---------------------------------------------------------------------
Look at Logs / <device name> / Launch-<game>-<date>.log (open with Kate).
The last lines show which step it was on (Step 1/3 checking the NAS, 2/3
sending a waiting save, 3/3 looking for a newer save). Quick fixes:
  - Put  "SkipLaunchChecks": true  on that game in Games.json (the game just
    starts; it is still backed up afterwards).
  - Set "ConflictPolicy": "AutoNewest" so it never needs to ask you.

---------------------------------------------------------------------
11. THE BACKUPS FOLDER AND THE STEAM RESET  (new in 14.5.1)
---------------------------------------------------------------------
Everything the program keeps "just in case" now lives in  Backups/  next to
savemanager.py (the first start after upgrading moves the old files there):
  Backups/Games.json/          copies of Games.json (newest 20 kept)
  Backups/Steam shortcuts/     copies of Steam's shortcuts.vdf, named so you can tell them apart:
        shortcuts_<id>_<date>_before-setup_clean.vdf            = no manager lines in it (your original)
        shortcuts_<id>_<date>_before-reset_6-with-manager-lines.vdf = it had 6 managed shortcuts
        ..._older-copy_...   = the old dated copies from Steam's config folder (copied, not moved)
  Backups/Program versions/    the old program files from before each upgrade (upgrade --rollback uses these)
  Backups/Packages/           the upgrade .zip files you used

Steam setup (menu O) now asks:  1 = set up   2 = put a backup file back   3 = RESET
  RESET (or:  python savemanager.py steamsetup --reset) takes the manager's launch
  lines OUT of every shortcut and leaves everything else as it is (other shortcuts,
  names, icons, other launch options). A labelled copy is saved first. It also puts
  SteamMatches.json aside so the next setup matches games from scratch.
  It cannot undo a rename such as "(Disc 2)" - restore a backup file (option 2) for that.
  Old BackupService.bat text in a shortcut (v12) is not removed - delete it by hand.

---------------------------------------------------------------------
12. MOVING THE PROGRAM FOLDER / UPGRADING  (14.5.2)
---------------------------------------------------------------------
Steam shortcuts hold the full path of savemanager.py. Upgrading IN THE SAME FOLDER
keeps them working (upgrade only overwrites the files). If you move the folder (or
run a copy from a new folder), run:  menu O > 4 (relink)  or
    python savemanager.py steamsetup --relink
It points every manager launch line at the copy you run it from. The Health check
(K) warns when shortcuts start a different copy.
An upgrade zip may hold only the changed files (any program file will do).
Packages you used are kept in Backups/Packages.

---------------------------------------------------------------------
13. ONE ENTRY PER FILE  (memory cards: DuckStation .mcd)  (14.5.2)
---------------------------------------------------------------------
Add ONE entry like this to Games.json (paths as for your other entries):
  {
    "Name": "DuckStation cards",
    "PerFileSource": "%USERPROFILE%\\Documents\\DuckStation\\memcards",
    "PerFileSourceSteamDeck": "/Path/duckstation/saves",
    "PerFileGlob": "*.mcd",
    "PerFileLabel": "DuckStation",
    "Process": "duckstation-qt-x64-ReleaseLTCG",
    "Platform": "Emulators"
  }
Every card file becomes its own game ("DuckStation - Parasite Eve_1"), backed up and
synced on its own, so different cards changed on two devices never clash. Cards that
only exist on the NAS (made on the other device) are listed too and get pulled.
Steam shortcut for the emulator:  launchgroup DuckStation -- %command%
(checks and backs up every card). Remove the old "zEmu_PS1 - Duckstation*" entries
(or give them "SkipOn") once the card entries work, so the cards are not backed up twice.

---------------------------------------------------------------------
14. WHAT CHANGED IN 14.5.3
---------------------------------------------------------------------
  - Steam Deck: the menu no longer closes at once when started from a Steam shortcut or the
    desktop icon (Steam's game variables made every question answer itself with "nothing").
    It also waits for the Konsole window, so Steam does not switch back to the library.
  - Folder moves no longer change a folder while walking through it (the "for loop" error).
  - Upgrade packages are now complete (every program file), so upgrading from an old version works.
  - Zips are never moved when the program starts; the upgrade files them away after installing.
  - The first backup of a game on a device when the NAS already holds a different save of it now
    keeps the NAS's save as a Version instead of replacing it.
  - "switch" no longer crashes when per-game / per-file entries exist.
  - Steam setup keeps the game an already set up shortcut was made for, even if its name differs.

---------------------------------------------------------------------
15. WHAT CHANGED IN 14.5.4
---------------------------------------------------------------------
  - Sync / upload: a rename on the NAS that Windows refuses for a moment ("access denied" while the new
    files are still in use) is now retried for a few seconds instead of stopping everything.
  - One game (or one old version) that cannot be copied no longer ends the whole sync. It is listed at the
    end ("COULD NOT SYNC") and tried again next time.
  - The NAS copy is now finished in a safer order: Current, then meta.json, then the older versions.
    A problem copying versions can no longer leave a new Current with an old meta.json. Sync also puts
    the "upload in progress" marker on the game, like the normal upload does.
  - The PowerShell shortcut maker can no longer hang the program (20 second limit).
